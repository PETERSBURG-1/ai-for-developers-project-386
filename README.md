# Календарь звонков

[![hexlet-check](https://github.com/PETERSBURG-1/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/PETERSBURG-1/ai-for-developers-project-386/actions)

Сервис записи на звонок по мотивам Cal.com. Владелец календаря один и задан заранее:
он создаёт типы встреч и смотрит предстоящие записи. Гость без регистрации выбирает
тип встречи, свободный слот в ближайшие 14 дней и записывается на звонок.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Референс Cal.com

Изучен пользовательский путь Cal.com: владелец создаёт тип события (название,
описание, длительность, доступность) и делится ссылкой; гость открывает календарь,
выбирает дату и время, заполняет имя, email и заметки, подтверждает бронь; слот
исчезает из свободных, а запись появляется в списке владельца. Пересечения с уже
существующими встречами блокируются.

В нашем приложении сохраняем только этот базовый сценарий. За рамками: регистрация,
личные кабинеты, внешние календари, уведомления, видеоконференции, оплата, переносы
и отмены.

## Сценарий владельца

1. Владелец открывает раздел «Админка» — видит типы встреч и список предстоящих
   записей всех типов, отсортированный по времени начала.
2. Создаёт тип «Встреча 15 минут»: название, описание «Короткий тип события для
   быстрого слота», длительность 15 минут. Тип сразу появляется в каталоге для гостя.
3. При необходимости создаёт второй тип, например «Встреча 30 минут».
4. Когда гость записывается, в списке предстоящих появляется запись: дата и время,
   тип встречи, имя и email гостя, заметки.

## Сценарий гостя

1. Гость открывает главную страницу и нажимает «Записаться».
2. В каталоге выбирает тип события — карточка открывает календарь.
3. В календаре доступны 14 календарных дней, начиная с завтрашнего; окно скользящее.
   У каждого доступного дня показано количество свободных слотов для выбранного типа.
4. Гость выбирает день и свободное время. Рабочий день — 09:00–18:00 (Europe/Moscow),
   слот длится столько же, сколько тип встречи, старты идут с тем же шагом. Занятые
   слоты видны, но недоступны.
5. Нажимает «Продолжить», указывает имя, email и заметку, подтверждает бронирование.
6. Видит подтверждение: тип встречи, дата, время. Слот становится занятым, счётчик
   свободных слотов дня уменьшается. Эта же запись появляется у владельца в «Админке».

## Обязательные функции

- Каталог типов встреч с названием, описанием и длительностью.
- Админка: создание, редактирование и удаление типов; список предстоящих записей
  всех типов.
- Календарь на 14 дней и список слотов выбранного дня.
- Бронирование гостем без регистрации: имя, email, заметки.
- Запрет пересечений любых типов встреч, включая частичные; смежные интервалы
  разрешены (конец одной встречи может совпадать с началом следующей).
- Атомарная проверка занятости: два одновременных запроса не могут занять одно время.

## Ограничения

- Один владелец, задан заранее; авторизации и личных кабинетов нет.
- Нет интеграций с внешними календарями, уведомлений, видеозвонков и оплаты.
- Окно записи — 14 календарных дней, начиная с завтрашнего дня.
- Рабочие часы — 09:00–18:00 ежедневно, часовой пояс Europe/Moscow.
- Длительность слота равна длительности типа, шаг доступных стартов — тоже.
- Приложение собирается в Docker-образ и запускается в контейнере.
- Хранение — в памяти процесса: после перезапуска сервиса записи и созданные типы
  сбрасываются. (Уточняется на шаге выбора стека; при переходе на БД пункт обновим.)

## Генерация клиента

- Контракт API описывается на TypeSpec; из него генерируется OpenAPI 3.1.
- Для фронтенда генерируется клиентский SDK из OpenAPI; генератор проверяется
  до выбора стека.
- Серверные типы и маршруты генерируются, если выбранный фреймворк это поддерживает;
  иначе сервер реализуется по контракту и проверяется тестами.

## Стек

- TypeScript, Node.js 24, pnpm 12.
- Контракт: TypeSpec 1.18 → OpenAPI 3.1.
- Клиент и схемы: `@hey-api/openapi-ts` (SDK, типы, Zod).
- Бекенд: Fastify 5 + Zod.
- Фронтенд: Vite 8, React 19, Tailwind CSS 4, shadcn/ui.
- Тесты: Vitest. Линтер и форматтер: Oxlint + Oxfmt.
- Окружение и задачи: mise, pitchfork (daemons), hk (Git-хуки).
- Контейнер: Docker, один образ с API и собранным фронтендом.

## Установка

Установите [mise](https://mise.jdx.dev/installing-mise.html), затем:

```bash
git clone https://github.com/PETERSBURG-1/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise install
mise run setup
mise exec -- hk install --mise
```

`mise install` ставит зафиксированные версии Node.js, pnpm и инструментов проверок.
`mise run setup` устанавливает зависимости, `hk install` — Git-хуки.

## Использование

```bash
mise run dev
```

- Приложение: http://localhost:5173
- API: http://localhost:3000/api/health

Dev-серверы работают как daemons mise:

```bash
mise daemons status
mise daemons logs
mise daemons stop
```

Проверки:

```bash
mise run check
```

Команда запускает генерацию контракта, линтер, проверку типов, тесты и сборку.
Она же используется в GitHub Actions.

Docker:

```bash
mise run docker:build
mise run docker:run
```

Контейнер слушает http://localhost:3000 и раздаёт собранный фронтенд и API.

Подробности — в [CONTRIBUTING.md](CONTRIBUTING.md) и [AGENTS.md](AGENTS.md).
